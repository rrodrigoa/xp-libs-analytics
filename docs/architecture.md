# Snapshot architecture

The core imports independently of FastMCP. The SDK owns the trust boundary: restricted YAML → strict typed AST → context-local DatasetRegistry → pinned authorized snapshot → authorized field/type resolution → conservative cost plan → fixed Polars expression factories → bounded strict JSON. Ingestion discovers arbitrary JSON paths at runtime; no application schema or business rules are built in.

`DatasetRegistry` maps logical names to trusted snapshot-source descriptors, independently of storage representation. Each engine or create_context() owns an independent namespace. RecordsSnapshotSource refers to an immutable source snapshot rather than a DataFrame. DatasetStore stores copied JSON and schema text in frozen snapshots. Opaque random snapshot IDs stay internal and remain bound to trusted principals. Register rejects collisions; replace atomically admits and publishes a new revision; compare-and-swap expected revisions detect stale writes. Snapshot leases pin records through planning/execution; retired versions remain charged to storage until the last query releases them. Failed admission preserves the prior binding. Context closure retires all bindings but does not cancel pinned queries. Metadata excludes sample values and filters paths by host field policy. Request budgets are shared by owner within a store. Hosts own scopes, limits, clocks and identity; YAML cannot supply them.

Plans serialize the normalized query and contain immutable tuples of projected values/presence/null indicators, resolved types, a fingerprint, UTC bounds and conservative group/window/expansion estimates. Casts run before filters, so WHERE cannot hide bad values. Every admitted row contributes to typing and cast validation.

The Polars backend uses opaque internal columns and a closed registry. Window membership expands bounded native integer ranges aligned to the Unix epoch. Tests compare boundaries and overlap to an independent oracle. Missing group keys carry separate presence dimensions and `group_key_status` output metadata.

`isolated=True` executes an approved plan in a spawned process with OS CPU/memory limits; the parent terminates it on deadline. Local trusted SDK calls can avoid startup cost. The MCP factory defaults to isolated execution and disabled uploads. Parsing/admission remain bounded work in the host. Container deployments should disable network, drop privileges/capabilities, bound PIDs/memory/CPU and mount read-only product files.

The worker memory ceiling is absolute. POSIX address-space limits include native mappings and thread stacks; `POLARS_MAX_THREADS=2` bounds the worker thread pool. Host resources must also be constrained for hostile workloads. Recorded probes and benchmark RSS are under `docs/evidence`.

`interfaces.py` defines sources, JSON sink, input/output ports and separate query-definition/execution IDs. V1 has no incremental state, watermarks, joins, multi-input execution, user plugins or output egress. New execution modes require a new contract and tests.

MCP resources are read-only and allowlisted. Under modern MCP, local requests inherit launcher identity rather than a per-request connection ID. Remote hosts must supply transport authentication and a trusted principal or execution-context resolver; default HTTP data operations are denied.

MCP never accepts agent-supplied identity or context selectors. Authenticated principal contexts are isolated and policy views preserve names while applying current scopes/field restrictions. A context resolver can instead select a host-managed session/request context. Names in other contexts are indistinguishable from nonexistent names. Local stdio deliberately has one launcher context per process. Reserved register_stream rejects without consuming sources; no continuous semantics are implied.

The shared matching package owns strict rule models, Unicode normalization, bounded LIKE/Rust regex validation, per-query distinct RapidFuzz scoring and privacy-cleared diagnostics. Matching plans compile to native Polars expressions/membership without row UDFs. Typed datetime equality bypasses string matching after explicit casts. Safe independent nonfuzzy conjunctions can bound candidate work; OR/NOT branches are never pushed independently. There is no persistent derived-value cache. Regex/fuzzy and requested diagnostics default to the OS-limited worker; explain/validate counts candidates without running scorers. Optional diagnostics have an explicitly narrower post-all-filters/pre-aggregation leaf-hit scope. Entity inference is deferred; see docs/adr/entity-inference-deferred.md.
